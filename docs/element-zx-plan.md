## 2. Что это за машина

Настоящий Z80 на FPGA-плате Alchitry: 3.5 / 7 / 14 / 20 МГц без тактов ожидания, разгон
22 / 28 / 30 МГц. 2 МБ RAM, ещё 2 МБ с платой AA-RAM. Нет FDC: диски эмулирует esxDOS
поверх SD (DivSD). Вся расширенная периферия закрыта ZXi-портами и по умолчанию выключена:
программа сама её включает. Отсюда два вывода.

- Классическая часть почти готова: Pentagon 1024, DivSD, ULA+, Timex, TurboSound FM,
  SAA1099, Z80 DMA, Z-Controller, Gigascreen, мышь Kempston.
- Новая работа — это HGFX, URAM, FastDMA, SoundDMA, LCU, eINT, HRC/HRXC и SID.

`e_zxi_000` переключает на лету память и тайминг: 48K, 128/+2, +2A, Pentagon 128/512/1024,
Pentagon 4096, Didaktik Gama 80.

### Порты

| Порт | Назначение |
|---|---|
| `#7C3B` / `#7D3B` | Общие ZXi `g_zxi_NN`: индекс / данные |
| `#783B` / `#793B` | eLeMeNt ZXi `e_zxi_NN`: индекс / данные |
| `#FC3B` / `#FD3B` | ZX-Uno регистры. **Уже заняты мостом ZiFi** (`ZiFi::unoUartRead`), нужен общий диспетчер |
| `#703B`… `#773B` | Диапазон MB03+. На eLeMeNt должен отвечать «MB03+ нет» (см. §3) |
| `#07 #27 #47 #67 #53 #73` | Быстрое окно URAM: страница, параметры, зона |
| `#2B` | LIFO, 32 байта |
| `#0B` | Z80 DMA (совместим с MB-02) |
| `#6E3B/#6F3B`, `#FF/#1FF` | SAA1099 |
| `#6C3B/#6D3B` | SID |
| `#7E3B/#7F3B` | Зеркало TSFM |
| `#0F #1F #3F #4F #5F` | MonsterBlaster (Soundrive/Covox) |
| `#133B/#143B` | UART: TX/статус и RX/скорость |
| `#0003…#0F03` | RTC72421, регистр в старшем байте |
| `#FEDF`, `#3xDF` | Детект мыши, вторая мышь |
| `#9EFD`, `#9FFD` | Чтение `#FE` и `#FF` |

Регистры HGFX, FastDMA, SoundDMA, eINT и LCU2 — **окна в памяти**. Их адрес задаёт старший
байт (`g_zxi_022/023/041/049/051/061`), а срабатывают они на запись.

## 3. Что на самом деле нужно софту

Загрузчик Nether Earth (`NETHER.COD`, код с `#4000`) разобран. Он делает так.

1. Читает `e_zxi_0FF` и требует `(v & #F0) == #E0`.
2. Читает дату ядра из `e_zxi_0FE/FD/FC` и собирает её как дату FAT:
   `год<<9 | месяц<<5 | день`. Сравнивает с `#32CB` = **2025-06-11**. Старое ядро отвергается.
3. Читает `#703B`/`#773B` и проверяет `(v & #F0) == #30` — так он отличает MB03+.

Следствия для реализации:

- Штамп ядра должен отдавать свежую дату: 2026-10-12.
- `e_zxi_0FF` = `#E2` или выше. Документ называет `#E1` для плат v1.x; для v2 значение
  уточнить по другим программам.
- `.APP` содержит 23 `OUT` в порты URAM: без URAM этот класс игр не пойдёт.
- Программы лежат в `.TAR` или `.TAP`, запускаются через esxDOS: отдельный формат не нужен.
- Часть софта работает только на eLeMeNt, не на MB03+ (пометка `eZX` на странице): Another
  World, HGFX-HAM videos, PF 2026, LnxView.

## 4. Как ложится на архитектуру

**Решение: отдельная архитектура `A_ELM`**, как `A_NEXT`, `A_SAM` и `A_ENT` (romset `R_ELM`).
Это самостоятельная машина со сменой личности через `e_zxi_000`, а не вариант Pentagon. Весь
код в `src/speccy/machines/Element/`. Цена: правки примерно в 60 местах (`Z80Ops::is*`, тайминг
и аудио, ROM, меню, ограничения, снапшоты), столько сейчас упоминаний `A_SAM`. Базовая личность
— Pentagon 1024. Блоки HGFX/URAM/DMA не должны зависеть от машины: так позже можно будет сделать
из них MB03+ для 48K/128K.

| Узел | Решение |
|---|---|
| Порты | В `Ports::input/output` один байтовый тест `g_elm` + вызов из flash, как у ATM/SAM. Шина: без Beta, с DivSD |
| Окна памяти | В функции записи `CPU.cpp` бит шлюза в байте `atm_ro` (занято: окна 0-3, EP 6, шрифт Evo 7; проверить бит 5). За ним маска 8K-слотов и таблица 256 B по старшему байту: VRAM, регистры, палитра, FDMA, SDMA, eINT, LCU2. Запись идёт и в RAM, и в устройство |
| Быстрые пути | `exec_nocheck`, `blockRepeat`, `MemGates`, батчи INIR/LDIR обязаны уступать слотам с окнами, иначе запись пройдёт мимо устройства |
| URAM | Слоты уже 8K (Next). 2 МБ = 128 страниц `ram[]`; страница 8K = половина `ram[n]`, запись через `plugPtr16`-подобный вызов на слот. `wantedPages` = 128 |
| HGFX буферы | PSRAM, 128 КБ, резерв в `Buffer::pageBudget` (шаблон `Ft812::configuredBytes`) |
| Горячий код | Окно на адресах `.nxovl`: Next и eLeMeNt резидентны взаимоисключающе, в сессиях других машин SRAM не тратится |
| Рендер | Целая строка на тике, как `Sam::draw`, сначала на core0. На core1 — по замерам |
| Палитра | Механизм ts256 (липкая карта, банки, reduce) уже решает 256 true color на 184-240 слотах |
| 512 px | Packed-pair (Timex hi-res, DS80) |
| Вход в меню | `p_showElm` = butter PSRAM и `FlashRoms::romsUsable()` |

### Чего не получится сделать точно

| Режим | Ограничение | Предложение |
|---|---|---|
| HGFX 2, 512x192, 256 цветов | Пара fb даёт только 16x16 цветов | 16 лучших цветов за кадр (`p80Choose` с Next), или 256 px с усреднением; выбрать на реальном софте |
| HRXC, 32 цвета | Те же 16 на кадр | Выбор цветов за кадр. HRC с цветами ZX точен |
| HGFX 3, 512x384 | В fb максимум 288 строк; повторы строк 2,1 запрещены HDMI-пинг-понгом | Сначала пропуск строк. Точный вывод на 576p, см. ниже |
| HGFX 4/5, 720x546/576, 4 цвета | Строки не помещаются в fb | Показ через строку; режим 4 уже `obsolete` |
| HGFX 7, 360x288 | Только в режимах 360 px | На 640x480 обрезка |
| 256 цветов | Пул 184 слота (240 на TMDS) | Слияние ближайших цветов, как у Kolbass |
| 20 МГц | `multiplicator` — только степени двойки | Хранить 20 в регистре, реально 14 МГц, с ограничением как `next_clk_cap`. 28 МГц в реальном времени не гарантируется |
| Прерывание по лучу, смена палитры по строкам | Частично | HRC KeyColour и INT по строке (`g_zxi_01C/1D`) работают построчно; середина строки — нет |

**HGFX 3 на 576p: память есть, узкое место — ISR.** Этап 1 — пропуск строк. Этап 2 делаем, только
если замер ISR на DVp2w покажет запас:

- Память: 384 × 256 = 98 304 B, а fb на 576p уже 103 680 B. Те же байты нарезаются на 384 ряда по
  270 B, новая куча не нужна. Чанки fb: ряд не должен пересекать границу блока.
- Драйвер читает из ряда 360 B, то есть залезет в следующий ряд. Нужен вывод «поле + 256 B + поле».
  Поднять `FB_MAX_LINES` (289). Меню и оверлеи ждут обычную разметку: возвращать её, как `blVmapSuspend`.
- Line map 384 → 576 = повторы 2,1,2,1, а `hdmi_vmap_step` требует минимум 2 строки на ряд. Нужна
  доработка ISR. Рендеров на треть больше (384 вместо 288 за кадр), срок на ряд с повтором 1 — одна
  строка, ~33 мкс при ISR 19-23 мкс. Запас мал, проверять вместе с HDMI-аудио.
- 1024x768: 512x384 ложится ровно ×2, правило «≥ 2 строки» соблюдается. Нужен режим 4 выходных
  пикселя на байт с разными цветами в паре, не проверено. Только 540/504 МГц.
- 640x480: 240 рядов, остаётся пропуск строк.
- Super HiRes из pico-amiga (пара в один пиксель) для HGFX 3 не подходит: сжатие там горизонтальное
  2:1, а здесь вертикальное 4:3 и байт packed-pair занят. Годится как запасной путь без пар
  (TFT, TV): 512 px усредняются до 256, 136 средних цветов влезают в пул 184 слота.

## 5. Фазы

Каждая фаза заканчивается проверкой на DVp2w.

### Фаза 0. Машина и детект
Арка `A_ELM`, romset, меню, ROM Pentagon + esxDOS, DivSD принудительно, Beta выключен, ZXi-регистры как файл
значений с чтением. Отдаём ID, дату ядра, COREID `eLeMeNt ZX`, MB03+ отсутствует.
Сброс и `.pss` объявлены как «не поддерживается» до конца фаз.

Проверка: esxDOS загружается, `NETHER.COD` проходит детект и не уходит на `JP NZ,#4040`.

### Фаза 1. URAM
Зоны, области, порты `#07…#73`, Protect-режим, счётчик свободных страниц, `Fast`-раскладка.
Типы памяти 0, 2, 8, 9, потом LCU/FRAM.

Проверка: CHCKURAM. `tools/elm_sim.c` (redcode + модель, как `sam_sim`/`ep_sim`) для прогонов на ПК.

### Фаза 2. HGFX 1: основной режим
Окна VRAM/регистры/палитра, INK/ATTR/COPY, смещения, PlanarMask, два буфера, COPY_ALL и
ERASE_ALL со статусом занятости (~6144 T и ~1 мс), прозрачность индекса 0 над экраном ZX,
ZX/линейная раскладка, индексный бордюр, рендер 256x192. Чанк через окна памяти: прямой
указатель, запись через обработчик при `PlanarMask != FF`.

Проверка: HGFXSPRI, HGFXTEXT, HGFXPLOT, HGFXBIRD, Nether Earth. Хост-тест планара против
таблицы `HGFX-2EN` (пример 145/233/143 → 153).

### Фаза 3. FastDMA + LCU
FDMA: batch/skip, дробный skip, LDDR, fill, 24 бита, второй набор, SaveINT; копирование как один
проход с продвижением времени. CPU на это время стоит. LCU1 и LCU2. Хост-тест LCU по таблице
примеров из документа: она полная, включая деление на 0 и переполнение.

Проверка: FastDMA test, DMA Playfield Scroll, Another World.

### Фаза 4. Остальная графика
HRC, HRXC, KeyLayer, Radastan, HAM, FILL, PlanarWorkingWindow, HGFX 2/3/6/7, Pentagon hi-res
(`#EFF7` бит 1), страница 6 для экрана, ULA+ `Extra`.

Проверка: HRCDEMO, KLAYTEST, RADASHOW, HGFXHAM8, HGFNICCC.

### Фаза 5. Звук и ввод
SoundDMA 8 каналов (стерео, 16 бит на A, петли, разрешение источника в URAM; рендер рядом с
MoonSplit), MonsterBlaster на Covox, SAA на ZXi-портах, зеркало TSFM. Сканкоды и прерывание от
клавиатуры (`ZxEvoAvr::hidKey` уже переводит HID в set 2), вторая мышь, UART `#133B/#143B` на ZiFi.

Проверка: SDMAPLAY, Lnx AmigaMOD Player, Wi-Fi Setup, Sarah.

### Фаза 6. eINT и хвосты
Enhanced Interrupts (таймеры 114.6875 МГц, строки, клавиатура, таблица приоритетов), SafeNMI,
LIFO, RTC72421, переключение `e_zxi_000` на лету, Pentagon 4096, Gama 80, `.pss`.

Документ сам пишет про eINT «in progress»: сверять с программами.

### Отложено
**SID.** Ядра в проекте нет. Нужен новый модуль уровня reSID-lite, и он нужен только паре игр
(Monty on the Run, Masters of Magic) и плеерам. Отдельным проектом, можно и для Pico-Zx-Player.

**General Sound** есть только на ядре Au+; уже есть в эмуляторе, порты те же.

## 6. Риски

- **Нет RTL.** Поведение планарного чтения, момент применения палитры HGFX, точные такты
  `COPY_ALL`, тайминг FDMA под SoundDMA документированы слабо. Нужен LnxSpectrum (Windows;
  здесь `wine` не найден) или ответы автора.
- **Цена записи.** Запись в планар с `PlanarMask` — до 8 байт в PSRAM на один байт Z80. При
  кратных 8 смещениях это одна строка XIP-кэша, иначе две. На 14 МГц со спрайтами — главный
  неизвестный по FPS. Смотреть на HGFXSPRI в PERF-сборке.
- **Flash.** Образ DVp2 на 4 МБ уже занимает около 3.5 МБ. Правило проекта: что не влезло в
  4 МБ, идёт за флаг как `MOONSOUND`. Нужно измерить после фазы 2.
- **Куча 576p.** Окно кода + буферы строк отнимают кучу так же, как на Next. Окно делить с `.nxovl`.
- **Быстрые пути** Z80 — самый вероятный источник тихих ошибок: запись мимо устройства не падает,
  а просто не рисует. Нужен отладочный счётчик записей в окна.
- **Быстрая эволюция.** Ядро меняется (октябрь 2026: новые режимы и eINT). Ориентир — ревизия
  20261012, Reference скачать и сохранить в `debug/`.

## 7. Решения владельца (2026-11-01)

1. **Отдельная архитектура `A_ELM`** (сначала был принят romset, владелец изменил решение в тот же день).
2. **Сначала машина.** Карту MB03+ для 48K/128K не делаем, но граница модулей её допускает.
3. **Образ:** 16 МБ или ещё и 4 МБ — решается по замеру flash после фазы 2.
4. **HGFX 2 при >16 цветах:** 16 цветов на 512 px для текста, 256 цветов на 256 px для
   картинки, выбор по содержимому кадра. Сначала проверить на реальном софте.
5. **SID:** отдельный проект, в фазы 0-6 не входит.
